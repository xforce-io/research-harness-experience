## 4. 组织数字化现状的五大挑战

- **数据结构不一致**：不同系统、不同模态的数据存储及格式差异显著
- **数据语义模糊不清**：数据无法表达业务逻辑及因果关系，且跨系统数据语义不一致
- **缺乏动态实时数据**：访问的数据可能是昨天甚至上周的数据，无法实时响应变化
- **工具缺少统一管理**：成百上千的 API 及工具，Agent 难以选择和高效调用
- **身份碎片化**：同一身份在不同系统以及不同数据中有不同访问规则

### 5.2 核心组件

| 组件 | 职责 |
|------|------|
| **Decision Agent** | 面向业务目标自主进行任务规划，基于 AI Data Platform 获取高质量上下文并进行有效的运行时管理，抑制幻觉和上下文腐烂等问题，在权限管控下调用工具与技能，形成安全的"推理—风险评估—执行—反馈"自主业务闭环 |
| **AI Data Platform** | 采用非侵入式访问架构，通过业务知识网络，实现统一数据访问、统一执行、统一安全管控 |
| **Info Security Fabric (ISF)** | 以身份、权限与策略为统一入口，对数据访问、模型输出与工具调用实施端到端控制和审计，降低越权、泄露与提示注入带来的安全风险，保障系统可管控 |
| **Trace AI** | 基于全链路可观测与证据链穿透，支持问题回放定位和自动优化建议，赋能 AI 应用实现可解释和可追溯 |

### 7.2 BKN 四大特性

- **统一业务语义**：业务知识网络采用数据、逻辑、风险、行动的概念模型，描述组织中的业务定义、关系、规则，从而避免语义不清晰、不一致、不完整
- **易开发、易理解、易集成**：通过概念规范、MD 开发描述语言，实现对开发者、智能体的开发友好，降低专有数据的开发和集成难度
- **实现语义级的安全**：信息安全及访问管控可按业务对象、业务规则进行设计及运用，让智能体具备语义级的安全管控能力
- **实现非侵入式数据访问架构**：通过语义层与数据层分离，引进数据虚拟化架构，实现不同数据源的零复制集成

## 10. 业务知识网络如何为决策智能体提供高质量上下文

### 10.1 核心价值点

- **上下文爆炸可收敛**：多源候选先经 BKN 语义网络组织与聚合，再由 Context Loader 统一精排仅保留关键证据与约束，避免海量片段直塞提示词导致决策失焦，并将整体准确率达到 93% 以上
- **长上下文腐烂可缓解**：以"实时事实 + 证据引用"替代生硬长文叠加，让推理围绕稳定对象展开，降低超长输入下的遗忘与幻觉风险，在各类型场景下准确率相比同类型平台提升 15% 以上
- **上下文污染可隔离**：通过 BKN 网络准确构建企业数字孪生，把低可信内容、矛盾信息与潜在注入风险挡在知识与执行边界之外，保证推理链路干净可控
- **Token 成本可压缩**：将多种材料转为结构化对象信息按需获取而非全文拼接，在相同预算下提升信息密度，实现准确率提升情况下平均 Token 下降 30% 以上

### 10.2 推理路径

```

   ↓ 统一返回 / 统一压缩 ↑

   ↓ 概念召回 / 对象召回 / 算子下推 / 子图扩展 ↑

   ↓ 下推计算 / 半自动构建知识网络 ↑

```

## 11. 业务知识网络如何提供安全执行能力

### 11.1 核心价值点

- **可解释决策**：以"对象–动作–规则–约束"的知识结构表达业务意图，把工具调用与参数选择落到明确语义边界与规则依据上，解释清楚"为什么这么做"
- **可追溯证据链**：从行动意图→知识节点→数据来源→映射/算子→最终调用全链路留痕，支持按实体/关系回溯到源数据与生效规则，做到可审计、可复盘
- **可管控执行闭环**：统一身份与访问控制绑定到知识网络的对象/动作权限，执行前置校验、执行中策略拦截、执行后审计回写，实现"可授权、可批准、可收敛"的安全闭环
- **可风险预防机制**：将风险建模为"风险类"并与行动类关联，执行前做风险评估与仿真，命中阈值自动降级/阻断/二次确认，把高风险动作挡在执行之前

## 12. ISF：基于数据聚合能力解决身份与权限碎片化

```
┌─────────────────────────────┐
│  信息安全编织 (ISF)            │
│   - 统一访问控制              │
│   - 动态脱敏                  │
└─────────────────────────────┘
           ↑
┌─────────────────────────────┐
│  VEGA 虚拟化引擎 +            │
│  业务知识网络                  │
│   - 统一视图                  │
│   - 数据聚合                  │
│   - 语义消歧                  │
└─────────────────────────────┘
           ↑
   SQL / NoSQL / API / Heterogeneous Data
```

**关键设计原则**：把碎片化的问题全聚合起来之后完成统一。如果没有 VEGA、没有业务知识网络，ISF 就没办法发挥作用。

- ISF 建立在统一知识网络之上的安全层，对所有访问（人或 Agent）执行统一的策略
- 业务知识网络将原始数据转化为具有统一语义的"业务知识"，消除数据理解的歧义。这是安全管控的前提

## 13. 集成方案：双路径支持（OpenClaw 案例）

### 路径 A：文件直连
- OpenClaw Agent 可直接读取 *.bkn 中的数据映射、工具配置与参数绑定
- 在不依赖平台的情况下访问数据与调用工具
- 适用于离线、轻量化与简单场景部署

### 路径 B：Kweaver Core 托管
- OpenClaw Agent 通过 Context Loader 接入 KWeaver Core
- 由 BKN Engine、VEGA、Execution Factory 等能力提供统一语义、数据访问与执行代理
- 并结合 ISF、Trace AI 等机制支撑复杂业务场景下的治理与审计

### 双路径价值

- **可流通、可移植、轻量部署**（路径 A）
- **上下文更强、执行更稳、安全更可控**（路径 B）

## 14. 性能数据（F1 Bench 测试集）

F1 Bench 由 BIRD 测试集中 Formula-1 数据库混合 30 篇非结构化文档设计，测试智能体结合异构数据推理能力。

| 指标 | KWeaver Core | Dify 召回基线 |
|------|-------------|--------------|
| 整体准确率 | **92.96%** | 78.87% |
| SQL 浪费率 | **8.2%** | 24.5% |
| SQL 命中效率 | **0.226** | 0.137 |
| 总 SQL 调用次数 | **292** | 408 |

**指标定义**：
- **整体准确率**：Agent 最终给出正确答案的题目数量占比
- **SQL 浪费率**：答错题目所消耗的 SQL 调用次数占总 SQL 调用次数的比例。该值越低，说明每次 SQL 执行越精准
- **SQL 命中效率**：最终正确答案数 ÷ 总 SQL 调用次数。反映平均每条 SQL 对最终答题成功的贡献密度
- **总 SQL 调用次数**：Agent 在解题过程中调用 execute_sql 工具的总次数。在准确率更高的前提下调用次数更少，说明每次执行更加精准
